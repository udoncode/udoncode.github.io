## 1. 도메인 모델이란?

애플리케이션 제작의 첫걸음은 현실의 비즈니스 문제를 소프트웨어 세상으로 옮겨오는 것입니다.

- **도메인(Domain):** 애플리케이션이 해결해야 할 문제 영역 (예: 학생 관리 시스템)
- **도메인 모델:** 복잡한 현실 세계의 개념을 단순하게 추상화한 설계도입니다.
- **엔티티(Entity):** 비즈니스 데이터의 정체성(Identity)을 나타내는 핵심 객체입니다.

---

## 2. 레이어드 아키텍처 (Layered Architecture)

기능이 복잡해질수록 '관심사'에 따라 코드를 나누어야 합니다. 이를 정형화한 것이 **3계층 구조**입니다.

| **계층** | **주요 역할** | **특징** |
| --- | --- | --- |
| **Presentation** | UI 렌더링 및 사용자와의 통신 | 화면에 정보를 보여주고 입력을 받음 |
| **Business Logic** | 실제 프로그램의 규칙과 도메인 로직 | **애플리케이션의 중심부** |
| **Persistence** | 데이터의 저장(영속성)과 불러오기 | DB와의 직접적인 소통 담당 |

### 계층 간 통신 규칙

- **단방향 흐름:** 상위 계층에서 하위 계층으로만 흐릅니다.
- **직접 인접한 계층:** 각 계층은 바로 아래 계층의 인터페이스만 알고 있어야 합니다.

이 규칙을 통해 한 계층의 변경이 다른 계층에 전파되는 것을 방지하여 유지보수성을 높입니다.

---

## 3. 도메인 모델의 구현

도메인 모델은 오직 비즈니스 개념과 로직만 담아야 합니다. UI 렌더링이나 API 호출 같은 외적인 책임이 침범하는 것을 **관심사의 누수**라고 하며, 이는 재사용성과 유지보수성을 크게 떨어뜨립니다.

JPA는 이를 막기 위해 **POJO(순수 자바 객체)** 작성을 지원합니다. 다만, 하이버네이트의 내부 동작(Proxy 생성 및 리플렉션)을 위해 몇 가지 규칙을 지켜야 합니다.

### **엔티티 작성을 위한 POJO 규칙**

1. **기본 생성자 필수:** 하이버네이트가 내부적으로 객체를 생성할 때 필요합니다.
2. **final 키워드 지양:** 지연 로딩을 위한 Proxy 객체 생성을 방해하기 때문입니다.
3. **최상위 클래스 권장:** 구조적 명확성을 위해 권장됩니다.

## 4. 연관관계 구현

객체는 참조를 사용하고, DB는 외래 키를 사용합니다. JPA에서 양방향 연관관계를 맺을 때는 두 객체의 필드 모두 명시적으로 연결해야 합니다. 이를 위해 편의 메서드를 사용하는 것도 좋은 설계 방식입니다.

```java
public void addPost(Post post) {
    if (post == null) throw new IllegalArgumentException("Post cannot be null");
    
    this.posts.add(post); // 현재 객체(Writer)에 추가
    if (post.getWriter() != this) {
        post.setWriter(this); // 상대 객체(Post)에도 현재 객체 설정
    }
}
```

## 5. 메타데이터와 제약 조건
**메타데이터**(설정 정보)는 자바 객체를 DB 테이블과 어떻게 연결할지 알려주는 **매핑 지침서**입니다. 또한, 메타데이터에는 구조뿐만 아니라 데이터의 유효성 검사도 포함되어 있으므로 제약 조건을 선언적으로 표현할 수 있습니다.

- **매핑 메타데이터:** `@Entity`, `@Table`, `@Id`, `@Column` 등
- **데이터 검증(Bean Validation):** `@NotNull`, `@Size` 등을 활용해 도메인 모델 레벨에서 데이터의 무결성을 선언적으로 정의할 수 있습니다. 이는 SQL 실행 전 애플리케이션 단계에서 에러를 잡아내는 안전장치가 됩니다.

```java
@Entity // JPA 관리 대상 선언
@Table(name = "students") // DB 테이블명 지정
public class Student {

    @Id // PK 지정
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "student_number", nullable = false, unique = true)
    private String studentNumber;

    // 양방향 연관관계: 학생이 작성한 글 목록
    @OneToMany(mappedBy = "student")
    private List<Post> posts = new ArrayList<>();

    // 연관관계 편의 메서드 (객체 간 일관성 유지)
    public void addPost(Post post) {
        this.posts.add(post);
        if (post.getStudent() != this) {
            post.setStudent(this);
        }
    }
}
```
